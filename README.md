### فولدر `price_data`

داده‌ی قیمت تصحیح‌شده‌ی هر چهار دارایی (`AAPL.csv`، `IBM.csv`، `NFLX.csv`، `TSLA.csv`) — خروجی مستقیم بخش ۳.۲ نوت‌بوک — به‌همراه `correction_summary.json`، خلاصه‌ی راستی‌آزمایی هر تیکر در برابر جدول ۱ مقاله. جزئیات کامل روش تصحیح (تقسیم سهام، سود سهامی، و اصلاح تاریخ برش) در `report.md`، بخش «داده‌های مالی متفاوت» آمده است.

### فولدر `run_states`

اسنپ‌شات از وضعیت کامل هر اجرای نوت‌بوک (پارامترهای ورودی و تمام نتایج هر بخش)، به‌صورت فایل YAML خوانا، به ترتیب زمانی نام‌گذاری‌شده. تولید این فایل‌ها در بخش ۱۵ نوت‌بوک انجام می‌شود. **جدیدترین فایل** (`20260828_000406.yaml`) مطابق با نسخه‌ی فعلی `report.md` و نوت‌بوک است؛ فایل‌های قدیمی‌تر اسنپ‌شات‌های میانی این پروژه‌اند و صرفا برای تاریخچه نگه‌داری شده‌اند.

### فولدر `verification_scripts`

اسکریپت‌ها و نوت‌بوک‌های مستقلی که برای راستی‌آزمایی نوت‌بوک اصلی — هم در برابر مقاله، هم از نظر سازگاری درونی خودش — استفاده شدند. فهرست کامل، همراه با توضیح و نتیجه‌ی هر یک، در [`verification_scripts/README.md`](./verification_scripts/README.md) آمده است.

## فایل‌های اصلی

- فایل **[`report.md`](./report.md)** — گزارش نهایی. شامل فرمول‌بندی ریاضی مسئله، روش پیاده‌سازی، نتایج کامل، و تحلیل تفاوت‌ها با مقاله.

## اجرای محلی

### ۱. ساخت و فعال‌سازی محیط مجازی (venv)

**ویندوز:**

```powershell
py -V:3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

**لینوکس:**

```bash
pyenv shell 3.11.15
python -m venv .venv
source ./.venv/bin/activate
```

### ۲. نصب پیش‌نیازهای پایه

```bash
python -m pip install --upgrade pip
pip install ipykernel
```

پس از این مراحل، `.venv` را به‌عنوان kernel در Jupyter انتخاب کنید (`ipykernel install --user --name=.venv` در صورت نیاز) و `portfolio_vqe_buonaiuto2023.ipynb` را باز کنید.

بقیه‌ی وابستگی‌ها را خود نوت‌بوک در سلول دوم نصب می‌کند، با نسخه‌های ثابت‌شده‌ی همان مجموعه‌ای که نتایج cache‌شده با آن تولید شده‌اند (`qiskit==1.4.6`، `qiskit-algorithms==0.4.0`، `qiskit-optimization==0.7.0`، `qiskit-ibm-runtime==0.29.0`). این ثابت‌سازی اختیاری نیست: کلاس‌های `TwoLocal`، `RealAmplitudes` و `PauliTwoDesign` در Qiskit 2.0 حذف شده‌اند و نصب بدون قید نسخه، نوت‌بوک را در همان import اول ارور می‌دهند.

### ۳. نکته‌ی GPU

نوت‌بوک دستگاه و روش شبیه‌سازی را در زمان اجرا از خودِ Aer می‌پرسد (`AerSimulator().available_devices()`) و بر همان اساس تنظیم می‌کند: روی GPU از روش `statevector` و روی CPU از `matrix_product_state` استفاده می‌شود. اگر GPU در دسترس نباشد، همان سلول یک هشدار چاپ می‌کند — و آن هشدار را باید جدی گرفت: گزینه‌های sampler بخشی از کلید cache هستند، پس اجرای روی CPU همه‌ی پیکربندی‌ها را از صفر بازمحاسبه می‌کند (چندین ساعت). بسته‌ی `qiskit-aer-gpu` در نسخه‌ی ۰.۱۵.۱ متوقف شده و برای پایتون ۳.۱۳ به بعد wheel ندارد؛ نوت‌بوک در این حالت به‌طور خودکار `qiskit-aer-gpu-cu11` را امتحان می‌کند.
